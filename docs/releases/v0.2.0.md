# solseer v0.2.0 — more servers, less disappearing signals

Another little drop from this vibe-coded side project. More coverage, cards that remember a burst, and a grid for when you just want everything in front of you.

## Two pages, same three-second rhythm

- With a cookie configured, each poll fetches **pages 1 and 2**, back-to-back, on the same **3-second target interval**. The local cap is now **40 API attempts per rolling minute**.
- Up to **200 server entries per cycle**. Page 2 uses page 1's fresh cursor; duplicate server IDs contribute only one observation. The pair counts as **one heuristic poll**, not two.
- Successful page-1 readings still update if page 2 fails or is deferred. The activity timeline shows partial cycles and counts actual API requests separately from polls.
- Anonymous mode stays at **one page every 20.5 seconds / 3 attempts per minute**. Rate-limit cooldowns and authentication-error backoff still apply. The local cap does not guarantee Roblox will accept that rate.

## Signals that remember the burst — and notice the exit

- A real burst gets **60 seconds of visibility**. Fresh readings that retain population can extend that, up to **2 minutes from the original burst**. A flat server cannot start a new burst or keep renewing forever.
- A **−1 player change** marks a burst as declining. It leaves the signals after the **next completed poll** unless a new qualifying burst appears. A **−2 or larger drop** removes it immediately.
- After a stale gap of more than **20 seconds**, the returning count becomes a fresh baseline. A second actual observation must establish new growth; an old count jumping to a new count cannot revive an old lead.
- Holding, full, recent, and declining states are labeled separately. A plateau is not a fresh notification.

## A little more context, another way to browse

- **Carousel / Cards** switches between the rotating view and an index of signal cards. Both sort by **population, highest first**, with signal priority breaking ties. Join, copy, graphs, and details work in either view.
- Cards and details compare a server's population slope with similarly populated servers over comparable **3–15 second** observation windows. At least **20 comparable peers** are needed for a percentile; otherwise it says there isn't enough data.
- Peer comparisons add ranking context, not biome confidence. Desktop notifications and the corner notice still prioritize actionable growth rather than simply picking the fullest server.

The early triggers stay the same: **net +2 within 15 seconds at 13–18 players**, or **net +3 within 10 seconds at 13+ players**, with an open slot for notifications. These are population leads, not confirmed rare biomes. Manual server hoppers and friend groups can still look like a rush.

## Updating

1. Stop the old app with **Ctrl+C**.
2. Download **solseer-v0.2.0-windows-x64.zip** and extract the entire ZIP into a new folder.
3. Open the `solseer` folder and double-click **Start solseer.cmd**. No separate Node.js installation is needed.

Saved cookie configuration and notification preferences remain in your local settings folder. Population history and join-click history start fresh with the new backend session. Roblox must be installed and signed in to use Join/Rejoin.

**147 automated tests pass**, plus HTTP/SSE/settings/join-handoff checks against the extracted Windows package and its bundled runtime. Polling tests use synthetic responses, not live authenticated Roblox traffic. The download excludes cookies, personal settings, and session data. It is a portable browser-app launcher, not a signed installer or native desktop executable.
